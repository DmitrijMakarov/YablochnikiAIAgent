# Паспорта метрик и данных

Все окна в относительном плановом году, часовой пояс Europe/Moscow; выгрузка с UTC timestamp, преобразование перед агрегацией. Фактической даты среза нет: это проект расчёта, не выгрузка клиентов.

|Метрика|Единица/числитель|Знаменатель и окно|Источник, наблюдаемость|
|---|---|---|---|
|Подключённые семьи|Разные группы с организатором и >=1 участником на31.12|Доступные100000 домохозяйств для доли; один домохозяйственный ID|Реестр состава, исключение известных повторов; неизвестный ID отдельно|
|Активные семьи|Подключённые31.12 группы с просмотром общего остатка или успешным выделением в декабре|Все подключённые31.12; группа один раз|Серверные события, автоматическое предупреждение не считается действием|
|Активация14дней|Группа с первым подходящим действием после вступления участника и <=14дней от создания|Все созданные01.10–31.12, включая неответивших; срез не ранее14.01 следующего года|Created, accepted, first_valid_action; окна поздних групп не обрезать|

|Оплаченные номеро-месяцы|Сумма разностей вероятностей оплаченного обслуживания одинаковых исходных номеров по календарным месяцам|Все исходно назначенные номера, включая вышедшие из группы|Платежи/оказанные услуги, не факт приглашения/перевода; возраст и календарь отдельно|
|Донорский вред|Семьи с новым ограничением другого участника из-за переноса пакета в7дней|Все назначенные семьи, фиксированный до назначения состав|Не отбирать по согласию после назначения; общий пакет создаёт зависимость внутри семьи|

Баланс пилота: N eligible = assigned + not_assigned(reason). N assigned = complete7d + immature + missing; для missing приоритет причин: недоступен журнал, невалидна связь ID, прочее. Unknown outcome не кодируется нулём. На Q2 печатаются реальные k/n и числа причин в каждой ветви; сейчас все фактические количества неизвестны. Граница полного наблюдения>=99% — проектный порог; анализ primary с нижней/верхней границей исходов пропусков, успех должен сохраняться в неблагоприятной границе. Не исключать закрывших номер: связь с ограничениями и платежами сохранять по исходному ID.

Когортная чувствительность: семь дней primary против14дней вторично; причина «исчерпание выделенного объёма» против любых ограничений вторично; Q2 против новых впервые подходящих Q3/Q4. Фактических k/n нет; устойчивость не проверена. Влияние состава: тариф и исходный размер семьи, общие веса контроля, отдельная категория unknown; без общей поддержки не подставлять нули. Финансовая чувствительность к задержке старта и удержанию находится в sensitivity.json.
