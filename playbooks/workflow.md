# Рабочий процесс и форматы

Команды выполняются из корня репозитория. Если используется виртуальное окружение, активируйте его перед запуском.

```sh
python -m tools.case init CASE
python -m tools.case begin CASE scope --environment Codex
python -m tools.case finish CASE
python -m tools.case begin CASE research --environment Codex
python -m tools.case ingest CASE S-001@1
python -m tools.case verify CASE --research-only
python -m tools.case finish CASE
python -m tools.case begin CASE strategy --environment Codex
python -m tools.case verify CASE
python -m tools.case finish CASE
```

Между командами заполните указанные ниже артефакты. Во время фазы `strategy` выполните [содержательную проверку](../.agents/skills/check-evidence/SKILL.md) и запишите аудит перед полным `verify`. В Cursor укажите `--environment Cursor`. Если интерфейс показывает модель, передайте `--model` при открытии фазы. Состояние `awaiting_decision` означает, что рекомендации проверены и ждут выбора. `begin CASE decision` выполняйте после выбора, а `finish CASE --human 'краткое подтверждение выбора'` после записи `decisions.md`. В решении укажите ID, дату, выбранную альтернативу, версии доказательств, владельцев, сроки, метрики и условия пересмотра.

## Файлы

- `inputs.json` разрешает источники по ID. Укажите один из `path` относительно `inputs/` и `url` (точный публичный HTTPS URL), а также `kind` со значением `own`, `public` или `synthetic`. Не включайте ключи, закрытые данные или URL с секретами. Не повышайте доверие к файлу по его имени.
- Для разрешённого ручного захвата страницы можно добавить `snapshot` относительно `inputs/` и `capture_note` со способом, датой и границей охвата. Это JSONL с парами `locator` и `text` точных видимых фрагментов. Сохраняйте URL оригинала. При ошибке CLI и успешном доступе штатным веб-инструментом сохраните обе записи. При расширении поиска человеком обновите разрешённый список и бюджет.
- `brief.md` содержит исходный запрос, решение, получателя, рамки, допущения и предельные затраты. `research.md` содержит план, сопоставление источников и влияние пробелов.
- `claims.tsv` имеет колонки `id type status statement source locator quote basis scope`. Для `fact` укажите ID версии источника, точный локатор и дословный фрагмент. Для `inference`, `hypothesis`, `forecast` указывайте ранее записанные ID через запятую без пробелов в `basis`, а допущения и пределы применимости в `scope`. Для гипотезы допустимо отсутствие оснований. В текстах используйте маркеры `[[C-001]]`. Статусы `active`, `disputed`, `superseded`, `withdrawn`.
- `sources.tsv`, `evidence/`, `state.json` и `run.tsv` ведёт CLI. Исходные данные хранятся отдельно от извлечений. `strategy.md` и `quality.md` создаются агентом. Для расчёта сохраните входы, скрипт или формулу и результат в кейсе либо со ссылкой на версию кода в репозитории.
- В новых кейсах `audit.tsv` содержит колонки `id verdict rationale`, разделённые табуляцией, и ровно одну строку на каждое активное утверждение. Используйте `supported` для факта, подтверждённого фрагментом, и `bounded` для вывода, гипотезы или прогноза с проверенными основаниями и границами. `needs_revision` блокирует закрытие фазы. В обосновании укажите, что именно во фрагменте поддерживает факт или как из оснований следует вывод и где он ограничен. Пустые, дублированные и лишние записи отклоняются.
- `log CASE --tool ... --status ok|error|retry|unknown` записывает действия вне CLI. Если статистика появилась после закрытия фазы, используйте `--step PHASE`. Для длительности передайте фактический ISO 8601 старт с часовым поясом через `--started`. Без старта фиксируется момент записи. При наличии статистики укажите `--tokens measured VALUE` или `--cost estimated 'VALUE CURRENCY'` с `--measurement`, где записаны источник, период и метод. Неизвестные значения оставьте пустыми. Длительность фазы включает время ожидания, а не только время модели.

## Что проверяет CLI

- `verify --research-only` сверяет завершённые артефакты с контрольной точкой, реестр источников с манифестом, хеши выписок и локальных оригиналов, соответствие ручного захвата выписке, локаторы, наличие цитат и ссылки между утверждениями.
- Полный `verify` добавляет проверку структуры стратегии и записей `audit.tsv`. В JSON `audit_structure` принимает значения `checked`, `legacy_unrecorded` или `not_requested`. Хеш аудита входит в новую контрольную точку стратегии. Кейсы, созданные до введения аудита, сохраняют исходные требования к контрольной точке.
- Связь цитаты с формулировкой, силу возражений и корректность смыслового вердикта оценивает автор аудита. CLI проверяет заполнение полей и покрытие ID. Для исправления завершённого кейса создайте отдельный кейс-ревизию с новой контрольной точкой. Укажите родительский кейс и затронутые ID в брифе. Новому захвату или изменённому оригиналу назначьте новую версию источника, а неизменённые материалы сохраняйте с прежними ID.

## Остановка, восстановление и сопровождение

Для остановки после безопасной записи выполните `pause CASE --reason '…'`. В новом чате сначала выполните `resume CASE --environment Codex`. Для готовой к запуску фазы `strategy` достаточно брифа, исследования, реестра утверждений и выписок для проверки существенных ссылок. Читайте журнал и частичные выходы при незакрытой фазе. Продолжайте ту же попытку после сверки. Подтверждённая запись фазы и совпадающие хеши закрываются автоматически. Для прерванного сетевого обращения со статусом `started` сначала выясните исход. Используйте уже сохранённое извлечение или ручной захват после подтверждения доступа. Повторный HTTP-запрос с неясным исходом CLI блокирует. Если данные изменились, сохраните старые входы и артефакты и назначьте новую версию источника или новый рабочий кейс.

Для сопровождения прочтите `decisions.md` и найдите просроченные действия, достигнутые пороги и новые данные. При пересмотре используйте новый кейс, сошлитесь в его брифе на прежний кейс и ID решения. Зафиксируйте, какие утверждения затронуты, что подтверждается по новым первичным данным и что остаётся спорным. Обновление решения требует явного выбора пользователя. Старые стратегии и ответы агента помогают найти первичные материалы, но не заменяют их.
