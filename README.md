# Стратег Фабрики продуктов

Репозиторий для агента в Codex и Cursor. Агент исследует продуктовый запрос, проверяет основания, предлагает альтернативы и готовит продуктовую и коммуникационную стратегии. Исходники, состояние и результаты хранятся в папке кейса. Для локальных процедур используется небольшой CLI. Модель работает в выбранной IDE под её учётной записью.

## Подготовка

1. Откройте корень репозитория в Codex или Cursor. В Cursor используйте режим Agent с доступом к терминалу и файлам проекта.
2. Установите Python 3.10 или новее и зависимости. Они нужны для прямого чтения PDF, DOCX и XLSX. Для CSV, TSV, Markdown, TXT и веб-снимков достаточно стандартной библиотеки.

   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   python -m tools.case --help
   ```

   В PowerShell активируйте окружение через `./.venv/Scripts/Activate.ps1`. Если IDE запускает каждый вызов в новой оболочке, укажите агенту путь к Python из окружения. При уже доступном Python с этими библиотеками можно использовать его. Отдельный API-ключ для локального CLI не нужен. Доступ к модели и связанные расходы зависят от выбранной IDE.

3. Начните новый чат в открытом проекте. Агент использует [AGENTS.md](AGENTS.md) и открывает нужный skill по ссылке из этого файла. Единый каталог [`.agents/skills/`](.agents/skills/) обнаруживается обеими IDE. Для чтения вручную в `AGENTS.md` есть ссылки на те же файлы.

## Новый кейс

Попросите агента в чате:

> Начни кейс cases/local/retention. Нужно решить, стоит ли менять первый экран сервиса. Цель — повысить завершение первого действия. Публичные сайты пока не разрешаю. Лимит прямых веб-запросов — 0. Продолжай до проверенной рекомендации.

Агент создаст папку через `python -m tools.case init cases/local/retention`. Добавьте разрешённые материалы в `inputs/` и укажите их агенту. Если доступ к данным и расходы уже оговорены, агент может сам заполнить `inputs.json` и бриф. Не включайте секреты, закрытые данные компаний и персональные данные. Пример разрешённого входа:

```json
{
  "web_requests": 0,
  "sources": [
    {"id": "S-001@1", "kind": "own", "path": "metrics.xlsx"}
  ]
}
```

Итог смотрите в `strategy.md`. `quality.md` описывает проведённые проверки, а `audit.tsv` хранит обоснование оценки каждого активного утверждения в новых кейсах. Связь с источниками проходит через `claims.tsv`, `sources.tsv` и извлечения в `evidence/`. `state.json` хранит следующую фазу, а `run.tsv` — попытки, ошибки, длительности и доступные сведения о расходах. Фаза `awaiting_decision` означает, что стратегия готова к рассмотрению. Сообщите агенту свой выбор, чтобы он записал решение и обязательства.

## Повтор пилота

Актуальные основания учебного результата находятся в [ревизии 2](cases/pilot-v2/quality.md). [Исходный пилот](cases/pilot/strategy.md) сохранён вместе со своей контрольной точкой. Стратегия в обеих ревизиях одинакова. Пилот использует авторский DOCX, таблицу фактических результатов технического теста и фрагменты RFC. Технический тест использует авторские образцы и ничего не утверждает о клиентах.

Для свежего прогона копируйте только исходники в новую папку. Пример для bash или zsh:

```sh
mkdir -p cases/local/pilot-copy/inputs
cp -R cases/pilot-v2/inputs/. cases/local/pilot-copy/inputs/
cp cases/pilot-v2/inputs.json cases/pilot-v2/request.md cases/local/pilot-copy/
```

В новом чате:

> Начни кейс cases/local/pilot-copy по request.md. Используй приложенный снимок RFC и не делай прямых веб-запросов. Проведи исследование и приостановись перед стратегией.

Проверка опубликованного результата и локальных процедур:

```sh
python -m tools.case verify cases/pilot
python -m tools.case verify cases/pilot-v2
python -m tools.case resume cases/pilot-v2
python -m cases.pilot.benchmark cases/pilot/inputs/compatibility.csv
python -m unittest discover -s tests -v
```

## Остановка и новый чат

Напишите «Приостанови кейс cases/local/pilot-copy и сохрани контрольную точку». После прерывания или в новом чате напишите «Продолжи кейс cases/local/pilot-copy по файлам». Для проверки состояния из терминала используйте `python -m tools.case resume cases/local/pilot-copy`. История старого чата для восстановления не нужна. При незавершённой попытке агент сверит журнал и файлы, прежде чем продолжать. Используйте один пишущий сеанс на кейс. Для повторного исследования с изменёнными исходниками создайте новую ревизию, чтобы сохранить основания прежнего решения.

## Границы прототипа

- PDF читается по текстовому слою, DOCX по абзацам и строкам таблиц, CSV/TSV по физическим строкам, XLSX по листам и строкам с сохранёнными значениями. OCR, сложная разметка и пересчёт формул не входят в прототип. Используйте проверенный текстовый экспорт со ссылкой на оригинал, если текстового слоя или вычисленных значений нет.
- Прямой веб-доступ использует явно разрешённый HTTPS URL из манифеста, установленный лимит запросов и сетевые разрешения среды. Поддерживаются статические HTML и обычный текст. Перенаправления, вход в аккаунт и выполнение JavaScript отключены. Если прямой доступ недоступен, CLI фиксирует причину. Разрешённый снимок с исходным URL и локатором можно зарегистрировать отдельно.
- CLI проверяет хеши завершённых фаз, происхождение, совпадение цитат с выписками, структуру стратегии и заполнение аудита. Значение `audit_structure: checked` означает прохождение проверки структуры. Смысловую оценку выполняет автор аудита по сохранённым фрагментам. У старых кейсов `legacy_unrecorded` обозначает исходный формат без `audit.tsv`. При проверке затрат `unknown` означает отсутствие данных. Интервалы в журнале показывают время между зафиксированными действиями, а не полное время модели или пользователя. Для подробностей см. [рабочий процесс](playbooks/workflow.md).
- Сопровождение выполняется в активном сеансе по запросу. Для проверки новых сведений используйте отдельную ревизию кейса с привязкой к прежнему решению.
